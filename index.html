Project 01 · AI Product

Job Tracker · AI 求职助手

job-tracker-qqmail
背景 · Background

秋招阶段求职申请分散在邮箱中，投递进度、笔面试通知、拒信信息零散混乱，人工整理效率低且易遗漏，面试准备缺乏针对性的结构化指引。

AI 介入点 · Where AI Helps
  • 邮件分类与信息抽取：调用 Claude（Haiku 模型做邮件初筛分类，Sonnet 模型做结构化信息提取），自动从 Gmail 中识别求职相关邮件，抽取公司、岗位、进度、时间等核心字段
  • 内容生成：基于公司与岗位信息，生成公司文化快照、面试流程拆解、分模块面试准备清单、定制化行为面试题
判断与修正 · Human Judgment
  • 针对 AI 邮件分类的误判问题（非求职邮件混入、状态识别偏差），新增手动编辑状态、删除错误条目功能，同时优化前置过滤规则，降低误判率
  • 针对 AI 生成的面试内容过于泛化的问题，限定输出框架与岗位维度，保留用户自主编辑、保存答案的能力，输出结果仅作为基础素材
  • 针对信息抽取字段不准确的问题，设计字段校验规则，所有抽取结果支持手动修正，不强制覆盖人工判断
最终结果 · Result

落地完整的求职追踪 Web 应用，包含邮箱自动同步、状态仪表盘、公司快照、面试准备、行为题练习五大模块；实现求职流程全链路结构化管理，大幅降低信息整理成本，支持 Demo 模式直接体验完整流程。

技术栈 · Stack
Claude API Gmail 集成 Vibe Coding Web App
Project 02 · AI Workbench

Content Copilot · 达人管理工作台

content-copilot-liquid-glass
背景 · Background

内容运营团队达人资源分散管理，内容审核标准不统一，Brief 下发效率低，缺少一站式的达人运营工作台，同时需要打造符合品牌调性的液态玻璃视觉风格。

AI 介入点 · Where AI Helps
  • 规则与模板生成：借助 Claude 生成内容审核标准框架、达人 Brief 通用模板、数据指标体系初稿
  • 视觉与代码辅助：用 Figma AI 辅助探索液态玻璃风格的样式方案，用 AI 辅助生成基础页面结构代码
判断与修正 · Human Judgment
  • 审核规则层面：AI 生成的通用规则过于宽泛，结合实际运营场景细化审核维度与扣分标准，形成可落地的执行 SOP
  • 视觉风格层面：AI 产出的液态玻璃效果过于夸张、对比度高，调整透明度、模糊度与光影参数，兼顾质感与长时间使用的舒适度
  • 页面结构层面：AI 生成的代码逻辑冗余，按照功能模块做分层重构，梳理达人管理、内容审核、Brief 配置三大核心流程
最终结果 · Result

落地完整的达人运营工作台，涵盖达人清单、内容审核、Brief 设置、数据分析四大功能模块；统一液态玻璃设计语言，提升达人运营全流程协作效率。

Project 03 · Interactive Web

Tarot Star · 塔罗占卜交互网页

tarot-star
背景 · Background

传统在线塔罗占卜页面交互形式单一，沉浸感不足；同时 GitHub Pages 部署下外部图片资源加载慢、失败率高，手势交互首次加载延迟高，严重影响用户体验。

AI 介入点 · Where AI Helps
  • 内容生成：借助 Claude 生成塔罗牌基础解读文案、深度解读内容框架
  • 性能与交互方案：用 AI 辅助分析页面性能瓶颈，输出预加载、资源优化的技术方案思路
判断与修正 · Human Judgment
  • 文案层面：AI 生成的解读内容过于模板化、缺乏占卜的沉浸感，结合传统塔罗牌义体系做二次润色，统一口语化表达风格，拆分基础解读与深度解读两层内容
  • 性能优化层面：AI 给出的优化方案偏通用，结合 GitHub Pages 的部署特性，选择将全部图片转为 base64 内联消除外部请求，新增 modulepreload 预取手势依赖，针对性解决首屏加载慢的问题
  • 交互层面：验证 AI 建议的手势交互逻辑，调整触发阈值与反馈动画，保证操作精准不误触
最终结果 · Result

完成沉浸式塔罗占卜网页，支持抽牌、深度解读、星盘映射等功能；通过资源内联与预加载优化，消除外部资源请求，大幅提升首屏加载速度与页面稳定性。

技术栈 · Stack
HTML / CSS / JS Canvas 手势交互 base64 资源内联 Claude
